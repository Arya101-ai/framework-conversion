How it works

Four steps, and the run is the specification.

1Bring your suite

Keep your tests exactly as they are. Point them at the TestMu grid: for most frameworks a configuration change, not a code change.

You provideExisting tests, a test environment, test accounts
2Run it on TestMu

Each test becomes a session that records every browser command with its arguments and response, plus network logs, video and screenshots.

OutputOne session per test. Also your baseline.
3The TestMu MCP writes Playwright

An AI agent reads each command log, rebuilds steps, locators, data and assertions, merges data-only variants, and generates a Page Object Model project.

OutputPlaywright tests, page objects, test data, central config
4Compare before and after

Migrated tests run on TestMu with the same browser and OS, under the original test names, side by side.

OutputTwo TestMu builds and a before/after report
No source codeYou don't hand over source code or rewrite anything first. The run itself is the specification.

Source: "How it works" in the offer document.
